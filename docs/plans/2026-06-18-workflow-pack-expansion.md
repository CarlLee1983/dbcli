# Workflow Pack Expansion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a v1.33-ready Workflow Pack Expansion that turns the v1.32.0 skill surface into a compact task-pack router for database review, migration review, safe backfill verification, and slow endpoint investigation.

**Architecture:** Keep this milestone data-driven. New workflow capability is added as Markdown task packs under `assets/tasks/`; the existing task loader discovers them without a TypeScript registry change. Skill files only get concise routing prose, then generated plugin/skill copies are synced with the existing script.

**Tech Stack:** Bun, `bun:test`, dbcli Agent Task Packs (`assets/tasks/*.md`), existing task parser/planner in `src/core/agent-tasks/`, skill sync/parity scripts.

- [ ] **Step 2: Add the task pack**

Create `assets/tasks/pr-database-review.md`:

```markdown
---
name: pr-database-review
description: Review a PR's changed persistence paths, queries and migrations for database risk before merge.
tags: [review, safety, readonly]
engines: [postgres, mysql]
params:
  query:
    type: string
    required: true
    description: The most significant changed SQL/persistence statement to analyze (not executed by this task).
safety:
  mode: plan-only
  requires:
    - blacklist-list
    - schema-check
steps:
  - type: command
    command: blacklist list
    reason: Confirm protected tables and columns before reviewing changed queries or exports.
    risk: readonly
  - type: command
    command: inspect --format json
    reason: Capture connection, permission tier, schema-cache and snippet context.
    risk: readonly
  - type: command
    command: plan "{{query}}"
    reason: Analyze the riskiest changed statement's scope and safety without executing it.
    risk: readonly
---
# Agent Notes

Use this task when reviewing a pull request that changes persistence paths:
queries, ORM models, migrations, exports, fixtures, reports or background jobs.
This task only plans; it never writes. Re-run `plan "<sql>"` for each material
changed statement, and cross-check `blacklist list` against any new serialized,
logged, exported or fixture-backed fields.
```

```markdown
---
name: migration-review
description: Capture pre-change schema evidence and preview a migration's DDL before it is applied.
tags: [migration, schema, readonly]
engines: [postgres, mysql]
params:
  table:
    type: string
    required: true
    description: The table the migration alters (exact name; confirm via `dbcli list`).
  ddl:
    type: string
    required: true
    description: The migration DDL statement to preview (not executed by this task).
safety:
  mode: plan-only
  requires:
    - blacklist-list
    - schema-check
steps:
  - type: command
    command: blacklist list
    reason: Confirm the migration target is not protected before previewing changes.
    risk: readonly
  - type: command
    command: schema {{table}} --format json
    reason: Capture the pre-change live schema as evidence.
    risk: readonly
  - type: command
    command: plan "{{ddl}}"
    reason: Preview the migration DDL's risk and scope without executing it.
    risk: readonly
---
# Agent Notes

Use this task before applying a schema migration. It only plans; it never runs
DDL. Save the pre-change `schema {{table}} --format json` output, preview the DDL
with `plan "{{ddl}}"`, then re-run schema/diff checks after the migration lands
through the project's normal migration tool. Any index or DDL suggestion from a
performance investigation should pass through this pack before writing.
```

- [ ] **Step 2: Add the task pack**

Create `assets/tasks/safe-backfill-verify.md`:

```markdown
---
name: safe-backfill-verify
description: Plan a safe backfill/UPDATE and a read-back assertion that verifies the write achieved its goal.
tags: [data, write, safety, verification]
engines: [postgres, mysql]
params:
  table:
    type: string
    required: true
    description: The table the backfill writes to (exact name; confirm via `dbcli list`).
  query:
    type: string
    required: true
    description: The backfill UPDATE statement to analyze (not executed by this task).
  verify_query:
    type: string
    required: true
    description: A read-only SELECT, usually count(*), that proves the backfill outcome.
  expect:
    type: string
    required: true
    description: The assertion expression for `assert --expect`, such as "rows == 0".
safety:
  mode: plan-only
  requires:
    - blacklist-list
    - schema-check
steps:
  - type: command
    command: blacklist list
    reason: Confirm the target table and columns are not protected before planning a write.
    risk: readonly
  - type: command
    command: schema {{table}} --format json
    reason: Verify exact column names and types before planning the backfill.
    risk: readonly
  - type: command
    command: plan "{{query}}"
    reason: Analyze the UPDATE's risk and scope without executing it.
    risk: readonly
  - type: command
    command: assert "{{verify_query}}" --expect "{{expect}}"
    reason: Read-back verification command for after the write is executed separately.
    risk: readonly
---
# Agent Notes

Use this task when a backfill must be safe and provable. This task only plans.
The execution sequence remains manual: capture scope, run dry-run, execute through
the approved write command, then re-run the generated `assert` command. Treat the
result as verified only when the read-back assertion passes.
```

Create `assets/tasks/slow-endpoint-investigation.md`:

```markdown
---
name: slow-endpoint-investigation
description: Connect proxy, explain and missing-index evidence to investigate a slow endpoint's query.
tags: [diagnostics, performance, readonly]
engines: [postgres, mysql]
params:
  query:
    type: string
    required: true
    description: The suspected slow SQL statement behind the endpoint (not executed by this task).
safety:
  mode: plan-only
  requires:
    - blacklist-list
steps:
  - type: command
    command: blacklist list
    reason: Confirm sensitive tables and columns are protected before inspecting query internals.
    risk: readonly
  - type: command
    command: proxy analyze --format json
    reason: Aggregate observed slow queries and N+1 patterns from the local proxy event log.
    risk: readonly
  - type: command
    command: explain "{{query}}"
    reason: Inspect the suspected statement's query plan.
    risk: readonly
  - type: command
    command: guide missing-index-for "{{query}}" --format json
    reason: Get advisory index candidates for migration review.
    risk: readonly
---
# Agent Notes

Use this task when an endpoint is slow and proxy logs or a suspected SQL query
are available. Start from observed evidence, then inspect the plan and index
candidate. Index advice is advisory only: route any proposed index through
`migration-review` before writing.
```
