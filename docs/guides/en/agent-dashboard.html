Analytical delivery

Turn one business question into a shareable data dashboard.

A dashboard is not done when SQL finishes. A reliable delivery explains where the data came from, which limits applied, and how its readers should interpret the result.

Situation: Operations asks, “Which plan saw the worst churn this month?” They need a result they can discuss, not an agent response with no trail back to the data.

A safe workflow

Confirm what may be seen

Read the blacklist first so the report cannot include protected tables or fields.

dbcli blacklist list

Use schema instead of guessing columns

Inspect the actual table before asking the agent to write a bounded query.

dbcli schema subscriptions --format json

Reuse team queries and deliver an interactive result

Look for a saved snippet first; once confirmed, run it with the interactive UI. Existing permissions, blacklists, and row limits still protect the result.

dbcli queries search churn
dbcli q @monthly-churn --ui

What dbcli will not do for you

It will not claim causation for you, and it will not let a dashboard bypass data protection. The result is a reviewable delivery; people who know the business context still make the conclusion.
