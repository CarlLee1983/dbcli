審查交付

法遵要一份證明，不等於要一份資料庫備份。

發版審查通常只需要知道「哪個主張連到哪份驗證」。把 SQL、資料列和憑證丟進附件，反而讓審查變得危險又難讀。Evidence Pack 留下的是可驗證的索引。

這次要交的東西：審查者問「這次客戶狀態修正有沒有做完驗證？」他不該拿到 SQL、資料列、憑證或完整 audit。團隊需要一份可保存、可驗證、但有邊界的摘要。

把散落的證據整理成一份審查材料

先把人要主張的話寫清楚

claims 檔只放 subject 與自然語言 claim，每一條都有 id 與文字。例如「客戶狀態修正已完成驗證」；這是送審主張，不是 dbcli 自己下的結論。

只引用既有證據，組成新 pack

pack 參照既有 verification、audit 與 receipt，輸出必須留在工作區，也不會覆寫已存在的檔案。這讓審查可以回到來源，又不複製來源內容。

dbcli evidence compose --claims ./claims.json --verification ver_abcd --audit 1a2b --receipt .dbcli/evidence/verify-receipt.json --output .dbcli/evidence/review.json

寄出前先驗證完整性

validate 檢查 SHA-256 digest 與來源是否還在；render 則在目前 blacklist 政策下輸出有效 pack。來源日後過期，歷史 pack 仍能被閱讀，但會誠實標記狀態。

dbcli evidence validate --file .dbcli/evidence/review.json --format json
dbcli evidence render --file .dbcli/evidence/review.json

dbcli 不會替你做什麼

Evidence Pack 不會連線，也不會複製 SQL、target、audit metadata、verification summary 或憑證。它驗證參照與完整性，不會把 claims 變成證明。
