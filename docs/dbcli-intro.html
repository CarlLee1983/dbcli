看看 Agent 背後執行了什麼 
dbcli blacklist list
dbcli schema subscriptions --format json
dbcli query "WITH months AS (SELECT date_trunc('month', CURRENT_DATE) AS month_start UNION ALL SELECT date_trunc('month', CURRENT_DATE) - INTERVAL '1 month'), rates AS (SELECT m.month_start, s.plan, COUNT(*) FILTER (WHERE s.cancelled_at >= m.month_start AND s.cancelled_at < m.month_start + INTERVAL '1 month')::numeric / NULLIF(COUNT(*) FILTER (WHERE s.created_at < m.month_start AND (s.cancelled_at IS NULL OR s.cancelled_at >= m.month_start)), 0) * 100 AS churn_rate FROM months m CROSS JOIN subscriptions s GROUP BY m.month_start, s.plan), compared AS (SELECT plan, churn_rate, LAG(churn_rate) OVER (PARTITION BY plan ORDER BY month_start) AS previous_rate, month_start FROM rates) SELECT plan, ROUND(churn_rate, 1) AS churn_rate_pct, ROUND((churn_rate - previous_rate) / NULLIF(previous_rate, 0) * 100, 1) AS increase_pct FROM compared WHERE month_start = date_trunc('month', CURRENT_DATE) ORDER BY increase_pct DESC" --recovery --ui
dbcli recover

Quickstart

把 dbcli 放進 Agent 的工具箱

Plugin／Skill 是最直接的 Agent 整合方式；若想先使用 CLI，也可以單獨初始化。

建議路線 · Plugin／Skill

直接安裝完整操作指引

Claude Code 可從 marketplace 安裝 plugin；Codex 可在 CLI 初始化後安裝 skill。

/plugin marketplace add CarlLee1983/dbcli
/plugin install dbcli@carllee1983-dbcli
dbcli skill --install codex

Skill 也支援 Claude Code、Cursor、GitHub Copilot、Gemini CLI、Antigravity 與 Windsurf。OpenCode 可搭配使用，但目前沒有專用 selector；請勿套用其他平台的安裝命令。

次要路線 · CLI

先建立連線設定

使用 bunx 執行初始化精靈；之後 Agent 可透過 skill 使用相同的安全工作流。

bunx @carllee1983/dbcli init

完成初始化後，再依使用的 Agent 安裝對應整合；完整平台說明請見使用者文件。

FAQ

常見問題

我不會寫 SQL，這工具跟我有關嗎？

正是為你設計的。你用自然語言請 Agent 處理資料，dbcli 讓 Agent 先用 schema 確認真實結構，再重用 saved queries 與 task packs 的專家查詢；你不必讀懂中間的 SQL，只需要檢查結果。

Agent 會不會不小心刪掉我的資料？

預設權限是 query-only，連 INSERT 都做不了。就算你開到 data-admin，DELETE 仍強制要求 WHERE 條件、建議先 dry-run，且等值限制讓「一句掃全表」在語法層就被擋下。DDL 更要 admin + --execute + DROP 加 --force 三重確認。

支援哪些資料庫？

支援 MySQL、PostgreSQL、MariaDB、MongoDB、Redis 與 Elasticsearch。同一專案可設定多條具名連線（例如 staging、production 或不同租戶），各自使用獨立憑證、權限與 schema 快取。

跟直接使用 MCP database server 有什麼不同？

dbcli 把權限與資料防護內建在資料庫操作層：憑證隔離、blacklist 遮罩、權限分級、dry-run、audit 與 recovery 都可直接使用。它不綁定單一 Agent 協定或編輯器，人類也能在終端機使用同一套工作流。

團隊要怎麼協作？

Saved queries 可放進 .dbcli-shared/ 並透過 git 與團隊共享；憑證可使用 --use-env-refs，讓每位成員與每條 CI pipeline 使用自己的環境變數，repository 不必保存明文密碼。

dbcli 會把我的資料庫密碼交給 Agent 嗎？

不會。dbcli 透過連線設定隔離憑證，Agent 使用固定的 dbcli 命令，不需要讀取或回傳密碼。

它只能讀取資料嗎？

不是。可用操作取決於設定的權限層級；寫入工作流可先 dry-run 預覽，再由明確授權執行。

Plugin 和 skill --install 該選哪個？

支援 plugin marketplace 的 Agent 可優先選 Plugin，安裝與更新更集中；已全域安裝 dbcli，或偏好 repo／使用者層級指引時，使用 dbcli skill --install <platform>。

查詢出錯時，Agent 會自己亂試嗎？

工作流會先確認 schema。若帶有 recovery 的命令失敗，dbcli 會產生修復計畫，讓 Agent 查看並只套用安全的修復步驟。
