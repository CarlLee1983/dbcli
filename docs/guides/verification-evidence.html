寫入後驗證

寫入不是通過；回讀驗證才是證據的起點。

將已核准的寫入留在 dbcli 外部執行，再用唯讀驗證與 receipt 記錄結果。

情境：安全 backfill 已由團隊在外部執行；現在需要重新檢查預期狀態，保留驗證文物與安全 provenance。

安全工作流

先做 preflight

驗證指令不會執行 UPDATE 或 DDL；先讓防護檢查回讀條件並取得精確的 after-write 指令。

dbcli verify safe-backfill --table users --query "UPDATE users SET status = 'active' WHERE status IS NULL" --verify-query "SELECT count(*)::int AS n FROM users WHERE status IS NULL" --expect "value == 0"

在外部寫入後執行 after-write

套用已核准的寫入後，使用同一情境執行回讀斷言並寫入 verification artifact。

dbcli verify safe-backfill ... --after-write --evidence-receipt .dbcli/evidence/verify-receipt.json

分開閱讀狀態與 receipt outcome

驗證情境可得到 verified、not_verified、indeterminate 或 blocked；receipt 另記錄 succeeded 或 failed provenance。

dbcli 不會替你做什麼

verify safe-backfill 永不執行 backfill 寫入。receipt 不含 SQL、rows、credentials 或使用者路徑，也不是執行核准；預檢不能建立 receipt。
