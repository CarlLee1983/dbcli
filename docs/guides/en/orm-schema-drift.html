Pre-deploy review

Your ORM describes one schema. Production may describe another.

The pre-deploy question should not be “should we apply the migration immediately?” It should be “what differs between the two sources, and is that difference intentional?”

Situation: A team is about to ship a service with changed ORM models. The database may have had manual corrections, delayed migrations, or a different version.

A safe workflow

Confirm protection and the full schema cache first

Check the blacklist, then read the full schema to create the live structural evidence and cache needed for ORM comparison.

dbcli blacklist list
dbcli schema --format json

Produce a drift report from the ORM definition

Use a supported ORM schema or snapshot as the comparison source so dbcli reports concrete differences rather than letting an agent infer from file names.

dbcli diff --against-orm ./drizzle/meta/0000_snapshot.json --format markdown

Keep the DDL decision in human review

Bring the report into migration review. dbcli can provide structural evidence and a suggested workflow, but executing DDL still requires explicit authorization and team review.

dbcli skill tasks plan migration-review \
  --param "table=<exact table name>" \
  --param "ddl=<captured dry-run DDL>"

What dbcli will not do for you

A schema-drift report is not a migration and does not change the database. It gives the team facts to discuss before anyone decides to create, alter, or apply DDL.
