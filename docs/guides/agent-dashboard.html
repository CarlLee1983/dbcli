分析交付

從一個業務問題，交付可分享的資料儀表板。

儀表板不是把 SQL 跑完就結束。可靠的交付要能說明資料從何而來、受哪些限制，以及閱讀者該如何解讀結果。

情境：營運團隊問：「這個月哪個方案的流失最嚴重？」他們要的是可討論的結果，不是一段無法追溯的 Agent 回覆。

安全工作流

先確認哪些資料能被看見

讀取 blacklist，確保報表不會把受保護表或欄位帶進結果。

dbcli blacklist list

用 schema 替代欄位猜測

先查看實際資料表，再請 Agent 撰寫限定範圍的查詢。

dbcli schema subscriptions --format json

優先重用團隊查詢，交付互動結果

先找保存的 snippet；確認後以互動式 UI 執行。查詢結果仍受既有權限、黑名單與筆數限制保護。

dbcli queries search churn
dbcli q @monthly-churn --ui

dbcli 不會替你做什麼

它不會替你宣稱因果關係，也不會讓儀表板繞過資料保護。結果是供人檢閱的交付物；商業結論仍需由熟悉情境的人判讀。
