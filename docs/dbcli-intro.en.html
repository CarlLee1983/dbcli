dbcli blacklist list
dbcli schema subscriptions --format json
dbcli query "WITH months AS (SELECT date_trunc('month', CURRENT_DATE) AS month_start UNION ALL SELECT date_trunc('month', CURRENT_DATE) - INTERVAL '1 month'), rates AS (SELECT m.month_start, s.plan, COUNT(*) FILTER (WHERE s.cancelled_at >= m.month_start AND s.cancelled_at < m.month_start + INTERVAL '1 month')::numeric / NULLIF(COUNT(*) FILTER (WHERE s.created_at < m.month_start AND (s.cancelled_at IS NULL OR s.cancelled_at >= m.month_start)), 0) * 100 AS churn_rate FROM months m CROSS JOIN subscriptions s GROUP BY m.month_start, s.plan), compared AS (SELECT plan, churn_rate, LAG(churn_rate) OVER (PARTITION BY plan ORDER BY month_start) AS previous_rate, month_start FROM rates) SELECT plan, ROUND(churn_rate, 1) AS churn_rate_pct, ROUND((churn_rate - previous_rate) / NULLIF(previous_rate, 0) * 100, 1) AS increase_pct FROM compared WHERE month_start = date_trunc('month', CURRENT_DATE) ORDER BY increase_pct DESC" --recovery --ui

Install the complete operating guide

Install the plugin from the Claude Code marketplace, or install the Codex skill after initializing the CLI.

/plugin marketplace add CarlLee1983/dbcli
/plugin install dbcli@carllee1983-dbcli
dbcli skill --install codex

The Skill also supports Claude Code, Cursor, GitHub Copilot, Gemini CLI, Antigravity, and Windsurf. OpenCode works with dbcli but currently has no dedicated selector; do not substitute another platform's install command.

FAQ

Frequently asked questions

I don't write SQL. Is dbcli still for me?

Yes. Ask your agent to work with data in plain language. dbcli has it confirm the real structure with schema, then reuse expert queries from saved queries and task packs. You only need to review the result, not decipher the SQL in between.

Could an agent accidentally delete my data?

The default permission is query-only, which cannot even INSERT. At data-admin, DELETE still requires a WHERE clause, recommends a dry run first, and equality-only conditions prevent broad table scans. DDL adds three more gates: admin, --execute, and --force for DROP.

Which databases are supported?

MySQL, PostgreSQL, MariaDB, MongoDB, Redis, and Elasticsearch. A project can hold multiple named connections—for staging, production, or separate tenants—with independent credentials, permissions, and schema caches.

How is this different from using an MCP database server directly?

dbcli builds permissions and data protection into the database operations layer: credential isolation, blacklist masking, permission tiers, dry runs, audit, and recovery are ready to use. It is not tied to one agent protocol or editor, and people can use the same workflow in a terminal.

How do teams collaborate?

Saved queries can live in .dbcli-shared/ and travel through git. Use --use-env-refs for credentials so every teammate and CI pipeline supplies its own environment variables while the repository remains free of plaintext passwords.

Will dbcli give my database password to the agent?

No. Connection profiles isolate credentials. The agent runs fixed dbcli commands and never needs to read or return the password.

Is dbcli read-only?

No. Available operations depend on the configured permission level. Write workflows can be previewed with a dry run and then executed only with explicit authorization.

Should I choose the Plugin or skill --install?

Choose the Plugin when your agent supports a plugin marketplace for centralized installation and updates. If dbcli is already installed globally, or you prefer repository- or user-level guidance, use dbcli skill --install <platform>.

Will the agent start guessing when a query fails?

The workflow confirms the schema first. If a command with recovery enabled fails, dbcli creates a recovery plan so the agent can inspect it and apply only safe remediation steps.
