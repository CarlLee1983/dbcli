資料庫門口
站著一個警衛

AI 助理想拿公司資料庫的資料。它不能自己開門，得先跟警衛講。警衛叫 dbcli。

這個警衛還有第二個身分：他也可以搬張椅子坐在走廊旁邊，什麼都不管，只記下誰走過去。

六種資料庫、六種講話方式。AI 只要學一種：跟警衛講。src/adapters/factory.ts

四把鑰匙

你拿到哪一把，就只能做那麼多事

鑰匙寫在設定檔裡。沒設定的話，預設是最小的那一把。src/types/index.ts:L101 · src/core/config.ts:L118

query-only 只能看

只能讀，而且一次最多端 1000 筆出來，免得整鍋被搬走。

read-write 可以改資料

新增、修改、刪除資料列。但不能動桌子本身。

data-admin 可以搬資料

比較粗重的資料活。仍然不是萬能鑰匙。

admin 什麼都能

連拆桌子（DROP、TRUNCATE）都行。警衛只會先喊一聲「你確定？」

才會變成你看到的答案

1

你的鑰匙夠不夠？

警衛先看這句話想做什麼：讀？寫？拆桌子？只放行「看得懂而且明確安全」的那些。看不懂就擋下來——寧可誤擋，不可誤放。

src/core/permission-guard.ts — whitelist approach

2

偷偷幫你加上 LIMIT 1000

拿著「只能看」鑰匙又沒自己寫上限時，警衛替你加。不然一句 SELECT * 就把一千萬筆倒進 AI 的腦袋。

3

這張桌子在黑名單上嗎？

不是只看第一張桌子——JOIN、逗號、UNION 牽到的每一張都要查。從側門繞進去也不行。

src/core/blacklist-validator.ts · issue #23

4

好，去拿資料

到這裡才真的碰到資料庫。翻譯機（adapter）把同一句話講成那個資料庫聽得懂的版本。

5

把敏感欄位塗黑再交出去

密碼、身分證、信用卡——資料回來了也不給看。而且黑名單最大：就算你用 --fields 點名要那一欄，也救不回來。

五關全過，你才拿得到答案。
任何一關說不行，就是不行。

單面鏡：站旁邊看，

最後一層 · querylens/

把數字翻成人話，
而且先把秘密塗掉

QueryLens 是報告產生器：同一份分析結果，輸出成一頁可以直接貼進 Pull Request 的 Markdown。

!

它永遠分析「影本」，不是正本

動手算之前，先把 SQL 裡的字面值全部拿掉——電話、Email、金額都不見，只留下句子的骨架。原始 log 一個字都沒改，但產出的報告從第一行就是安全的。

src/querylens/analyze.ts — redactEventsForAnalysis()

為什麼要多這一層？因為報告會被貼到 GitHub 上。「事後記得遮」會忘記，「先遮再算」不會。

警衛亭的內部

六個房間，各做一件事

commands/

櫃檯。67 個窗口：query、schema、export、blacklist…… 負責聽懂你要辦什麼，不負責決定能不能辦。

core/

腦袋。所有規則都在這裡：權限、黑名單、SQL 拆解、稽核紀錄。上面那五道關卡就住這一層。

adapters/

翻譯機。六種資料庫各一台。核心只認識一種講法，剩下的交給翻譯。

formatters/

打扮。同一份結果，要表格、要 JSON、還是要一張 HTML 報表，出門前換衣服。

proxy/

單面鏡。轉發、看懂協定、把事情寫成一行一行。它不屬於前面那五道關卡——那是另一條路。

querylens/

寫報告的。讀那些行，先遮掉字面值，再算成一份給人看的 Markdown。

還有 i18n/ 決定警衛講中文還是英文（DBCLI_LANG），以及 agent-core/——把警衛的判斷力包成套件，讓別的程式也能借去用。

一個小細節

問「你幾歲」的時候，
警衛不會先把六台翻譯機扛出來

執行 dbcli --version 只是要一個數字。程式進門先看一眼：如果只是問版本，就直接答，完全不去載那些資料庫驅動。 套件管理器和健康檢查一天問幾百次，這一眼省下的是真的時間。
