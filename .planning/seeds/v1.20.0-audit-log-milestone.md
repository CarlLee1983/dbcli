# v1.20.0 — Agent-Facing Audit Log

## Goal

讓 AI agent 跨 session / 跨 invocation 能讀回「dbcli 在這個 DB 上做過什麼」，補上目前 inspect / recovery envelope / report 共同缺失的「歷史活動」維度。

## Scope

### In Scope

- **Session handoff**：時間序列、操作摘要、影響範圍（tables / keys / index）、成敗
- **Forensics (success path)**：dry-run 結果、實際輸入摘要、輸出 row count
- **儲存與 rotation**：`.dbcli/audit/<connection>.jsonl`，size / entry cap
- **CLI**：`dbcli audit tail | show | clear`
- **Schema 合約**：audit entry 為 agent-facing JSON 合約，加 contract test（比照 v1.19.1）
- **Redaction**：強制套用 `tests/helpers/sensitive-output.ts` 規則到 SQL body / params
- **整合**：失敗時的 `recovery_ref` 雙向連結 recovery envelope；`side_effect_tier` 重用 capability registry
- **Config**：`.dbcli` 加 `audit.enabled` / `audit.rotation` 設定

### Out of Scope

- Tamper-evident / 加密 / 簽章（合規路線）
- 多年保留策略
- 並發資源索引（→ [[conflict-avoidance-resource-index]]）
- audit log 自動對照 query 結果驗證（→ [[self-verification-correlation]]）

## Phases (initial sketch — 待 `/gsd-new-milestone` 細化)

| Phase | 主題 | 概略內容 |
|-------|------|----------|
| P1 | Audit Writer + Storage | `AuditLogger` service、JSONL append、file lock、rotation；config schema 與 `audit.enabled` 開關 |
| P2 | Entry Schema 與 Redaction | Entry JSON 合約定型 + contract test；統一 redaction（SQL body / params / connection string）；side-effect tier 重用 |
| P3 | Hook 到所有 commands | 在 query / q / insert / update / delete / migrate / recovery 流程注入 audit write；Mongo / Redis / ES 全引擎覆蓋；blacklist 失敗 / permission 失敗 entry |
| P4 | CLI `audit` 指令 | `tail` / `show` / `clear`；輸出格式（table / JSON）；blacklist 與 sensitive-output 二次過濾 |
| P5 | Recovery envelope 連結 | 失敗路徑寫入 `recovery_ref`；recovery envelope 反向加 `audit_ref` 指向觸發 entry |
| P6 | Docs + Skill | SKILL.md 補 audit log 使用情境；agent guide 在 inspect / recovery 時自動引用 recent audit；en + zh-TW readme |

## Success Criteria

- AI agent 開新 session 後執行 `dbcli audit tail` 能拿到上一個 agent 的完整活動摘要
- 失敗 case 的 audit entry 能透過 `recovery_ref` 一鍵跳到 recovery envelope
- Release gate：原始 SQL body / params 絕不進 audit log（contract test + redaction test 雙保險）
- 所有引擎（SQL / Mongo / Redis / ES）一致格式輸出
- 既有 release gate 全綠（typecheck / test / lint / build）

## Trade-offs（從 [[notes/audit-logging-exploration]] 帶來）

- 每條指令一次 disk write — 接受；可關閉
- 多進程並發 — file lock，夠用
- PII 風險 — 必須 redaction，無例外

## Locked Decisions (2026-05-14)

| # | 決策 | 結論 |
|---|------|------|
| D1 | 預設啟用策略 | **預設 on（opt-out）**。`audit.enabled = true` 為 dbcli 出廠值；user 可在 `.dbcli` 設為 false 關閉 |
| D2 | session_id 來源 | **env 優先、缺則自動生成**。讀 `DBCLI_SESSION_ID`，無則 `<pid>-<unix-ts>-<random>`，並寫入 `.dbcli/last-session-id` 給同進程後續呼叫共用 |
| D3 | Result preview | **不包含**。Entry 僅紀錄 `target` / `rows_affected` / `success` / `redacted_sql`，不存 cell 值。forensics 需要時 agent 自行重跑 query 或讀 recovery envelope |
| D4 | Multi-connection 範圍 | **每連線一檔 + 全域 merge view**。儲存仍是 `.dbcli/audit/<connection>.jsonl`；`dbcli audit tail` 預設只看當前連線，`--all` flag 提供跨連線時序合併 |
| D5 | Tail layout | **純時序、最新在下**（reverse-chronological，類 `git log`）。session_id 作為 entry 欄位呈現 |
| D6 | 寫入失敗行為 | **stderr 警告 + 主指令照跑**。Audit log 為 observability、不是 safety gate。額外提供 `dbcli audit health` 讓 user 主動檢查 writer 狀態 |

## Implications

- D1 → 升級到 v1.20.0 的既有用戶會立刻看到 `.dbcli/audit/` 目錄出現；CHANGELOG / release note 需明確說明
- D2 → 需新增 module `src/services/session-id.ts`，並讓 agent 安裝器（Claude Code / Codex / Cursor / Windsurf / Gemini）有機會注入 `DBCLI_SESSION_ID`
- D3 → release gate 必須有 contract test：「audit entry 不得包含 result rows」
- D4 → P4 CLI 工作量稍增（merge view），但 storage / rotation / redaction 邏輯保持單純
- D5 → JSON 輸出格式（agent-facing）為扁平陣列；表格 / 人類輸出按時序印
- D6 → P1 需引入新指令 `audit health`，列入 P4 範圍
