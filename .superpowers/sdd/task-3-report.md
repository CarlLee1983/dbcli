## Source verification conclusions

The controller supplied current upstream verification, which was applied as the
documentation source of truth:

- TypeORM `schema:log` logs the SQL that `schema:sync` would execute without
  applying it.
- Current TypeORM `SchemaLogCommand` uses command `schema:log` and requires the
  data-source option `-d`. The documented Bun-compatible recipe is:
  `bunx typeorm schema:log -d <path/to/datasource> > schema.sql`.
- Current Sequelize CLI `db:migrate` exposes migration selection filters such as
  `to`, `from`, and `name`, but no universal `--dry-run`. The documentation does
  not claim that flag. It directs users to run migrations against an empty
  scratch database and dump the resulting schema.
- PostgreSQL `pg_dump --schema-only` dumps object definitions rather than data.
- MySQL `mysqldump --no-data <database> > schema.sql` dumps definitions without
  row data.

Primary references:

- https://typeorm.io/docs/using-cli
- https://github.com/typeorm/typeorm/blob/master/src/commands/SchemaLogCommand.ts
- https://github.com/sequelize/cli/blob/main/src/commands/migrate.js
- https://www.postgresql.org/docs/current/app-pgdump.html
- https://dev.mysql.com/doc/refman/8.4/en/mysqldump-definition-data-dumps.html
