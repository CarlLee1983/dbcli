Governed vocabulary · Change review

Make the evidence expectation for a business term explicit.

A semantic model defines the governed vocabulary. An optional reviewed contract can add an owner and descriptive evidence policy, so an agent has context for the term without inventing executable rules.

Situation: A customer metric or business term matters to release review. The team needs its canonical governed subjects, owner, and expected evidence to be inspectable before a related schema or workflow change.

A safe workflow

Keep contracts as a reviewed local artifact

Place dbcli.contracts.json beside the semantic file. Contracts use version 1, canonical names and subjects, a draft, approved, or deprecated status, and a descriptive evidence policy.

Validate, inspect, and search offline

Validate the artifact before relying on it, then use context or deterministic search to inspect the governed terms. These commands never connect or execute queries.

dbcli contract validate --format json
dbcli contract context --format json
dbcli contract search customer --format json
dbcli contract drift --format json

Use approved terms in ordinary agent context

Only valid approved contracts appear in ordinary context, search, and skill context. Draft and deprecated terms remain local review artifacts; drift shows whether the local evidence is valid, stale, invalid, or unavailable.

What dbcli will not do for you

A contract cannot contain SQL, credentials, protected identifiers, or executable rules. An evidence policy describes an expectation; it does not approve a change or replace verification. Missing or invalid explicitly requested contract evidence fails closed.
