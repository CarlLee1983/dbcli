上線前檢查

ORM 寫的是一套 schema，正式資料庫未必是另一套。

部署前的問題不該是「要不要直接套 migration」，而是「兩個來源實際上差在哪裡、差異是否符合意圖」。

情境：團隊正準備發布包含 ORM model 變動的服務。資料庫可能曾被手動修正、延後 migration，或處在不同版本。

安全工作流

先確認連線保護與完整 schema 快取

先確認黑名單，再讀取完整 schema，為 ORM 比對建立目前資料庫的結構證據與快取。

dbcli blacklist list
dbcli schema --format json

以 ORM 定義產生 drift 報告

將已支援的 ORM schema 或 snapshot 作為比較來源，讓 dbcli 輸出具體差異，而不是讓 Agent 根據檔名推斷。

dbcli diff --against-orm ./drizzle/meta/0000_snapshot.json --format markdown

由人審查 DDL 決定

把 drift 報告交給 migration review。dbcli 可提供結構證據與建議流程，但是否執行 DDL 仍需明確授權與團隊審查。

dbcli skill tasks plan migration-review \
  --param "table=<精確資料表名稱>" \
  --param "ddl=<已擷取的 dry-run DDL>"

dbcli 不會替你做什麼

schema drift 報告不是 migration，也不會自動變更資料庫。它讓團隊先討論事實，再決定是否建立、修改或套用 DDL。
