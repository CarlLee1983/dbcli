Release review · Offline handoff

Hand reviewers a compact evidence pack, not a pile of raw operational data.

A review needs clear claims and references to evidence, while SQL, targets, credentials, and database data should stay out of the handoff. dbcli composes a canonical local pack from existing evidence.

Situation: A release or compliance review needs to connect an externally supplied claim to already-recorded verification, audit, and receipt evidence without querying the database again.

A safe workflow

Write reviewable claims separately

Create a claims JSON file with exactly a subject and plain-language claims. Treat claims as supplied statements, not as dbcli verification verdicts.

Compose a workspace-contained pack

Reference existing verification artifacts, audit entries, and an optional receipt. The new canonical pack will not overwrite an existing file.

dbcli evidence compose --claims ./claims.json --verification ver_abcd --audit 1a2b --receipt .dbcli/evidence/verify-receipt.json --output .dbcli/evidence/review.json

Validate integrity, then render for history

Validate the SHA-256 digest and whether referenced source evidence is still available. A valid pack can still be rendered for historical review when retained sources later expire.

dbcli evidence validate --file .dbcli/evidence/review.json --format json
dbcli evidence render --file .dbcli/evidence/review.json

What dbcli will not do for you

evidence never queries a database and does not copy SQL, targets, audit metadata, verification summaries, or credentials into the pack. It validates evidence references and integrity; it does not turn claims into proof.
