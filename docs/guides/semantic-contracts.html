業務語意

讓重要指標有已審閱的語意與證據規則。

把 owner、業務術語和證據需求寫進可檢閱的契約，讓 agent context 與 schema 變更評估都有治理邊界。

情境：團隊希望保護訂單、客戶或營收指標；單靠欄位名稱不足以判斷變更風險。

安全工作流

建立可檢閱的契約檔

在 semantic 檔旁維護版本 1 的 dbcli.contracts.json。每份契約使用 canonical name 與 model:、field:、relationship: 或 metric: subject，並選擇 draft、approved 或 deprecated 狀態。

驗證並提供安全 context

先驗證檔案，再輸出或搜尋可供一般 agent 使用的已核准契約。

dbcli contract validate --format json
dbcli contract context --format json
dbcli contract search customer --format json

在 schema 演進前檢查 drift

evidence policy 可選 none、receipt-required 或 verification-required。在評估設計變更前檢查契約與本機 semantic 證據是否仍一致。

dbcli contract drift --format json

dbcli 不會替你做什麼

契約不得含 SQL、憑證、受保護識別字或可執行規則。所有 contract 指令都離線且唯讀；只有有效且 approved 的契約會進入一般 context。
