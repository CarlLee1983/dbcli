審查交付

把證據交給審查者，而不是把資料庫內容交出去。

Evidence Pack 將既有 audit、verification artifact 與 receipt 組成可驗證的本機審查包。

情境：發版或合規審查需要可保存的證據摘要，但審查者不應取得 SQL、資料列、憑證或完整 audit 細節。

安全工作流

用外部 claims 檔描述主張

claims 檔只包含 subject 與自然語言 claims；每個 claim 有 id 與文字。主張不是 dbcli 的驗證裁決。

明確組成一份新 pack

只參照既有 verification、audit 與 receipt；輸出須留在工作區內，且不會覆寫已存在的檔案。

dbcli evidence compose --claims ./claims.json --verification ver_abcd --audit 1a2b --receipt .dbcli/evidence/verify-receipt.json --output .dbcli/evidence/review.json

先驗證，再為歷史審閱輸出

validate 檢查 SHA-256 digest 與來源是否仍可取得；render 在目前 blacklist 政策下，不重讀原始參照地輸出有效 pack。

dbcli evidence validate --file .dbcli/evidence/review.json --format json
dbcli evidence render --file .dbcli/evidence/review.json

dbcli 不會替你做什麼

Evidence Pack 不會連線，也不會複製 SQL、target、audit metadata、verification summary 或憑證。來源日後消失時 validate 會回報 source-expired；仍可 render 已保存的 pack。

下一步

先完成寫入後驗證與 receipt，再將適合審查的證據組成 pack。
